\begin{frame}{Pour n'a-t-on pas perdu d'information?}
 
Parce qu'on peut reconstituer \alert{exactement} la relation complète
\vfill

    
\begin{redbullet}
  \item Connaissant un cas je connais l'identifiant du patient, 
     de la pathologie, du département
 \item Connaissant \texttt{idPatient}, je trouve l'unique patient 
     dans la table Patient (et je suis sûr qu'il existe)
     \item  Idem pour la pathologie, le département, et au-delà la région
\end{redbullet}

\vfill


\begin{blocgauche}
Ce raisonnement est implanté dans SQL grâce à la jointure
\end{blocgauche}

\end{frame}

\begin{frame}[fragile]{Quelques exemples}
 
Le plus simple

\begin{minted}{sql}
select  * from Patient where idDépt = 15
\end{minted}

\vfill

La jointure

\begin{minted}{sql}
select  d.nom as nomDépt, r.id, r.nom as nomRégion 
from Département as d, Région as r
where d.idRégion=r.id
\end{minted}

\vfill

Exploration de la hiérarchie avec jointure externe (\sqlkw{left join})

\begin{minted}{sql}
select  p1.intitulé as CodePatho, p2.intitulé as codeSousPatho
from Pathologie as p1 left join Pathologie as p2
on p1.code=p2.sousTypeDe
\end{minted}

\end{frame}


%%%%%%%%%%%%%%%
\begin{frame}[fragile]{Les agrégations}
 
Clauses \sqlkw{group by} et\sqlkw{having}

\vfill
Les régions et leur nombre de département

\begin{minted}{sql}
select  r.nom as nomRégion, count(*) as nbDépts 
from Département as d, Région as r
where d.idRégion=r.id
group by r.id
\end{minted}

\vfill
Les régions avec moins de 5 départements

\begin{minted}{sql}
select  r.nom as nomRégion, count(*) as nbDépts 
from Département as d, Région as r
where d.idRégion=r.id
group by r.id
having nbDépts <= 5
\end{minted}
\end{frame}

\begin{frame}[fragile]{Le problème des hiérarchies}
 
Courant dans les entrepôts de données (opération \texttt{rollup}). Difficile avec SQL

\vfill
Les pathologies de type cardiovasculaire (celles qui sont sous-type de 'cardio').

\begin{minted}{sql}
select  * 
from Cas as c 
where codePathologie in (
   select code from Pathologie where sousTypeDe='cardio')
\end{minted}

\vfill

Regroupement par super-type de pathologie, avec ROLLUP

\begin{minted}{sql}
select  superpatho.intitulé, count(*) as nb_cas
from Cas as c, Pathologie as patho, Pathologie as superpatho
where superpatho.code = patho.sousTypeDe
and patho.code = c.codePathologie
group by superpatho.intitulé with rollup
\end{minted}

\end{frame}

%%%%%%%%%%%%%%%
\begin{frame}[fragile]{Les vues}
 
Une option à toujours considérer\,: les vues
\vfill
\begin{minted}{sql}
create view CasParPathoSexeDept as
select  p.intitulé, pa.sexe, d.nom as nomDépt, count(*) as 'nb_cas'
from Cas as c, Pathologie as p, Département as d, Patient as pa
where c.codePathologie=p.code
and c.idDépt =d.id
and c.idPatient = pa.id
group by c.codePathologie, pa.sexe, d.id
\end{minted}

\vfill
L'interrogation devient beaucoup plus simple

\begin{minted}{sql}
select * from CasParPathoSexeDept
where nomDépt='Ardennes'
\end{minted}
\end{frame}

\begin{frame}{À retenir}


\begin{redbullet}
  \item SQL est un langage puissant et très flexible pour l'interrogation et l'agrégation 
      de données élémentaires
 \item Une limite pour les agrégations sur des hiérarchies (rollup) 
  \item Une limite (très relative) en performance pour de très grandes bases
  \item Les vues apportent simplicité et confidentialité
\end{redbullet}

\vfill

Les systèmes d'entrepôts de données (\textit{data warehouse}) 
combinent opérateurs spécialisés et outil d'exploration et visualisation.

\vfill
Passons à la pratique\,!

\end{frame}
